  1. Точка лута = пресет-спавнер. Каждый ящик, полка, труп — файл в Spawners\Presets. Имя читается как адрес: Buildings-Armory-TV_Bunker-World_Shelf = здание → оружейная → ТВ-бункер → полка у ТВ.
    2. 
        
  2. Записи выдачи. Nodes — ссылки на узлы дерева лута (конкретные предметы берутся из дерева); Items — прямой список предметов {Id, Rarity}; FixedItems — гарантированные предметы; Subpresets — вложенные наборы из других пресетов.
    3. 
        
  3. Шанс и количество. Probability (%) решает, сработает ли запись; QuantityMin..Max — сколько предметов выдаст за срабатывание; AllowDuplicates — может ли один предмет выпасть дважды за раз.
    4. 
        
  4. Редкость выбирает предмет. Внутри узла/группы шанс предмета зависит от Rarity: Abundant → Common → Uncommon → Rare → VeryRare → ExtremelyRare (от «часто» к «почти никогда»).
    5. 
        
  5. Кулдауны и зоны. Группа кулдауна предмета решает, вернётся ли взятый предмет и когда; ShouldFilterItemsByZone + Zones.json ограничивают спавн границами зон мода; AllowedLocations (Coastal/Continental/Mountain) — география предмета на карте.

ПОСТ-ДЕЙСТВИЯ (POSTSPAWNACTIONS) — НАБЛЮДАЕМЫЕ В БАЗЕ

      

      
ПОЧЕМУ WARNING «ID ПРЕДМЕТА ОТСУТСТВУЕТ В PARAMETERS.JSON»

      
Parameters.json — справочник спавнящихся предметов текущего экспорта (1137 записей). Пресеты порой ссылаются на Id, которых в нём нет: это «дырки» в сериях вариантов — например, у брони есть 01_01, 01_03 и 01_04, а 01_02 разработчики удалили из спавна, и ссылка на неё осталась в старом пресете. Игра при срабатывании записи молча пропускает неизвестный Id — остальные предметы записи спавнятся, поэтому это WARNING, а не ERROR. Такой «призрачный» предмет не появится в игре никогда: повышать ему Probability или менять Rarity бессмысленно. Для нового лута берите Id из вкладки ПРЕДМЕТЫ.

      
Описания построены на анализе 1400 файлов реального экспорта (наблюдаемые ключи и значения схемы) и общих механиках игры; то, что нельзя подтвердить документацией, помечено «наблюдение». Единицы времени кулдаунов файлом не декларируются. Все правки идут в WORKING-копию — файлы базы не меняются, ваниль восстанавливается кнопкой «СБРОСИТЬ ПРАВКУ».

Почему WARNING «Id предмета отсутствует в Parameters.json» — пресет ссылается на предмет, у которого в текущем экспорте нет параметров спавна. Почти всегда это «дырка» в серии вариантов: в базе есть Armor_Tactical_Vest_01_01/01_03/01_04, но нет 01_02 — вариант удалили из спавна в патчах, а ссылка в старом пресете осталась. Игра молча пропускает такой предмет: остальные предметы записи спавнятся как ни в чём не бывало — поэтому это WARNING, а не ERROR. Такой предмет не появится никогда; для нового лута берите Id из вкладки ПРЕДМЕТЫ (там только реально спавнящиеся). ERROR — это сломанные пути дерева (node-ref) и отсутствующие subpresets: там запись теряет смысл целиком.

Добавить предмет торговцу

  

    

    

      
      

    

  

  

    
    
    
  

  
Товары, уже присутствующие у торговца — по ID или по названию, — не показываются в списке; только что добавленные исчезают сразу. Одноимённые варианты с другим ID можно раскрыть кнопкой под списком. Для стандартных торговцев список ограничен ассортиментом их роли в SCUM (Оружейник — оружие и патроны, Охотник — луки и ловушки, Рыболов — рыбалка и т.д.); ручной ввод ID ниже работает без ограничений. ID, которого нет в базе, добавляется со статусом UNVERIFIED — приложение не подтверждает его существование в игре. Окно остаётся открытым для добавления нескольких позиций.

КАТАЛОГ ПРЕДМЕТОВ · ВЫБОР ДЛЯ ACCEPTEDITEMS

  

    
    
  

  

  
Клик по строке добавляет ID в выбранную группу предметов; диалог остаётся открытым — можно добавить несколько позиций. Уже имеющиеся в группе ID пропускаются. Позиции, которых нет в базе, добавляйте вручную в поле группы (они получат статус непроверенных).

  




  
—

  
Быстрая шпаргалка: Probability ↑ — запись срабатывает чаще; QuantityMax ↑ — больше предметов за раз; Rarity на класс ниже (Rare → Common) — предмет чаще выбирается из группы; FixedItems — гарантированный лут (удалить = меньше лута). Полный словарь — вкладка «СПРАВКА».

  
  
Правка сохраняется в WORKING-копию (data\loot-working.json) — файлы базы не меняются. Ванильный вариант восстанавливается кнопкой «СБРОСИТЬ ПРАВКУ» в карточке спавнера. Ссылки на дерево и предметы сверяются с базой при сохранении.

ДЕРЕВО ЛУТА · WORKING

  
  
Файл дерева: {"Name": "ItemLootTreeNodes.…", "Children": […]}. Публикация → Nodes\Override\<файл>.json — файл перекрывает одноимённый из Default/Current. Ключ ChildrenMergeMode задаётся на любом узле с Children: Replace — дети этого узла полностью заменяют детей одноимённой системной группы; Append — дети добавляются в конец к дефолтным (без ключа — замена файла целиком). Селектор ниже управляет корнем файла; на вложенных узлах ключ правится в JSON.

ДЕРЕВО ЛУТА · РЕДАКТОР

  
  

  
  
Rarity — класс редкости ветки (понижение класса = предметы ветки чаще); Merge — ChildrenMergeMode (Replace — заменить детей системной группы, Append — добавить в конец). Имена листьев — Item ID: подсказки из Parameters.json при вводе. [+] добавить ребёнка (узел становится группой), [⧉] копия узла, [×] удалить (кроме корня).
